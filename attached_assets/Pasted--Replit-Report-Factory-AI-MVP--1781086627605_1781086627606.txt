1. 使用者輸入報告主題
2. 選擇報告類型
3. 選擇報告風格
4. 產生結構完整的報告草稿
5. 顯示報告品質檢查項目

首頁需要包含：

1. Hero 區塊

   * 標題：Report Factory AI
   * 副標題：輸入主題，快速生成結構完整、格式清楚、可後續修改的專業報告草稿。
   * CTA 按鈕：開始生成報告
   * 次要按鈕：查看報告格式

2. 功能介紹區

   * 選擇類型
   * 生成報告

4. 報告生成表單區
   表單需要清楚、集中、好操作。

三、報告生成表單

請建立或優化以下欄位：

1. 報告主題

   * input 或 textarea
   * placeholder：例如：不同溫度對維生素C氧化速率之影響

2. 報告類型
   使用 select，選項包含：

   * 學校研究報告

   * 市場研究報告
   * 實驗報告

   * 社會議題報告

3. 報告風格
   使用 select，選項包含：

   * 簡潔條列

4. 報告長度
   使用 select，選項包含：

   * 短版摘要
   * 中等篇幅
   * 完整報告
   * 研究架構版

5. 生成按鈕
   按鈕文字：生成報告草稿

四、生成結果區

請讓生成結果顯示為清楚的報告格式，不要只是一大段文字。

生成結果至少包含：

1. 報告標題
2. 摘要
3. 研究背景
4. 研究目的
5. 研究問題
6. 研究假設
7. 文獻探討大綱
8. 研究方法
9. 預計圖表
10. 預計圖片
11. 研究限制
12. 結論草稿
13. 報告品質檢查表

如果目前沒有串接真正的 AI API，請先建立 mock generation function，根據使用者輸入的主題、報告類型、風格與長度，產生一份結構化假資料，但程式架構要方便之後接 OpenAI API。

請將生成邏輯整理成獨立 function，例如 generateReportDraft()，不要把所有邏輯塞在 UI 裡。

五、報告品質檢查表

生成結果下方請加入 checklist，包含：

* 是否有清楚研究目的
* 是否有研究問題
* 是否有研究假設
* 是否有文獻探討方向
* 是否有研究方法
* 是否有圖表規劃
* 是否有研究限制
* 是否可直接後續修改
* 是否符合正式報告語氣

每個項目可以用 check icon 或簡潔標記呈現。

六、操作功能

請加入以下按鈕：

1. 複製報告

   * 點擊後將生成結果純文字複製到剪貼簿
   * 顯示成功提示

2. 下載 Markdown

   * 將報告內容下載為 .md 檔案
   * 檔名可使用 report-draft.md

3. 清除內容

   * 清空表單與生成結果

4. 重新生成

   * 使用目前表單資料再次生成

七、視覺設計

請使用乾淨、專業、偏 SaaS 工具感的設計。

風格要求：

1. 背景：淺灰或米白
2. 主色：深藍、靛藍或墨綠擇一
3. 卡片：白底、圓角、細陰影
4. 字體：系統字體即可，中文要清楚
5. 按鈕：主按鈕明顯，hover 有回饋
6. 間距：不要擁擠，區塊之間要有留白
7. RWD：手機版也要能正常使用

請避免：

* 過度花俏
* 霓虹色
* 太多動畫
* 字太小
* 表單太擠
* 生成結果難閱讀
